# Security & Engineering Quality

## Rate limiting

`slowapi` middleware (`backend/app/core/rate_limit.py`), in-memory by default (zero mandatory infra),
switching to a Redis backend automatically when `REDIS_URL` is set — `docker-compose.yml` ships an optional
`redis` service (profile `redis`) for that story.

- Cheap reads (e.g. `GET /api/v1/msmes`): 60 requests/minute.
- Expensive compute (`POST /api/v1/counterfactual/run`, `POST /api/v1/risk/calculate`): 10 requests/minute.
- Every response carries `X-RateLimit-Limit` / `X-RateLimit-Remaining`; a limit breach returns HTTP 429 as
  `application/problem+json` (RFC 7807) with a `Retry-After` header.
- Covered by an automated test: `backend/tests/test_api_rate_limit.py`.

Rationale: a lender integrating at portfolio scale needs predictable, bounded cost from this API, not just
abuse protection — the tiering reflects actual compute cost per endpoint, not a single global number.

## Input validation

All request/response bodies are typed Pydantic v2 schemas (`backend/app/schemas/`) — no raw dicts cross the
API boundary. Invalid input is rejected at the FastAPI validation layer before it reaches any engine.

## Error handling

All 4xx/5xx responses use a consistent RFC 7807 `application/problem+json` shape
(`backend/app/core/errors.py`), not ad hoc error strings — this includes validation errors, not-found
errors, and rate-limit errors.

## Secrets handling

- No secret ever has a default checked into source; `.env.example` documents every variable with empty or
  clearly-dummy values.
- `.env` is gitignored (see `.gitignore`); `docker-compose.yml` reads it via `env_file`.
- Optional third-party integrations (Mapbox, live weather) are only ever read from environment variables
  and degrade gracefully to seeded/static data when absent (spec §22) — the app never requires a paid key
  to run.

## Observability

- Structured JSON logs (`structlog`) with a per-request `X-Request-ID` correlation ID, generated by
  middleware and echoed in both the response headers and every log line for that request
  (`backend/app/core/logging.py` / request-id middleware in `app/main.py`).
- `GET /api/v1/health` for liveness checks.

## OWASP-relevant checklist for this app's actual surface

- **Injection**: all DB access goes through SQLAlchemy's parameterized query builder — no raw string SQL
  concatenation.
- **Broken access control**: out of scope for this prototype (spec §29 places auth in P2/optional) — this
  is explicitly documented as a known gap, not silently ignored. See
  [`docs/adr/0004-no-auth-in-prototype.md`](adr/0004-no-auth-in-prototype.md).
- **Security misconfiguration**: CORS origins are explicit and env-driven (`CORS_ORIGINS`), never `*` in
  the default config.
- **Vulnerable/outdated components**: dependencies pinned to specific versions in
  `backend/requirements.txt` / `frontend/package.json`; see `docs/adr/0005-stack-currency.md` for the
  currency policy.
- **Insufficient logging**: addressed above via structured, correlated logging.

## CI

`.github/workflows/ci.yml` runs backend `pytest` + `ruff` + `mypy` and frontend `eslint` + `tsc` + `pnpm
build` + Vitest on every push, so these guarantees are continuously checked, not just true on the day this
was written.
